The database layer is still accessed using from db import get_session, and the usage remains the same as before. The backend should first create a session with session = get_session(), then perform operations using session.add(), session.query(), and session.commit(). The existing tables users, devices, and collection_requests remain unchanged in terms of fields, so the current APIs for user registration, device registration, and collection requests do not require modification. Two new tables have been added: RequestStatusLog and DataRetrievalRequest. If the system needs to record status changes, a RequestStatusLog record should be created when collection_requests.status is updated. If a user requests data retrieval service, a DataRetrievalRequest record should be created and linked to the corresponding device_id and consumer_id. Apart from these additional features, the rest of the backend logic can remain the same, and existing APIs should continue to work without major changes.

数据库层仍然通过 from db import get_session 获取数据库会话，使用方式与之前相同：先创建 session = get_session()，然后使用 session.add()、session.query()、session.commit() 完成数据库操作。原有三张表 users、devices、collection_requests 的字段没有改变，因此原来的用户注册、设备登记和回收请求相关 API 基本不需要修改。现在数据库中新增了两个表：RequestStatusLog 和 DataRetrievalRequest。如果系统需要记录请求状态变化，在更新 collection_requests.status 时额外创建一条 RequestStatusLog 记录并保存；如果用户选择数据恢复服务，则创建一条 DataRetrievalRequest 记录，并关联 device_id 和 consumer_id。除了这两个新增功能之外，其余主代码调用方式与之前保持一致，因此现有 API 逻辑基本无需调整，只需要在对应功能处新增数据库写入即可。
